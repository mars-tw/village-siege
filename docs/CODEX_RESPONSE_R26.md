# R26：修正移動跳動，接上出征目標

2026-10-02。App 1.2.0；共享規則 0.20.0、network 4、persistence 1。基準為已發布 1.1.1／8b6664bb。

## 人物移動

舊版本在格位改變時啟動 170ms tween，下一次約 100ms 的相同格位更新又直接設定角色位置，覆蓋還沒完成的位移。修正後，呈現座標持續向已知格位前進，相同位置更新不重啟或吸附；停止前走完剩餘距離，朝向使用原圖集。移動速度、地形、碰撞、命中及存檔權威規則不變。

工匠、戰士、弓箭手及持盾兵使用各自六方向原圖。其他單向真動作表依左右翻轉，沒有冒稱新增六套素材。慢速兵種與巨像依自己的步伐間隔平滑呈現；讀回舊檔時建立新呈現器，避免較舊 tick 被讀檔前的位置拒絕。

獨立 AI 體驗員透過正常介面匯入自己的實玩存檔，操作工匠與 150/150 邊境戰士的移動、停止與反向。修改版保留工匠 33 秒錄影／70 張截圖、戰士 31 秒／55 張截圖，未再觀察到舊版反覆跳回的抖動。這是實際可見操作觀察；銅色選取圈追蹤器會被同色建築吸走，沒有拿該座標推估宣稱通過。[修改前](evidence/r26/motion-before-summary.json)、[修改後](evidence/r26/motion-after-summary.json)

## 出征與載入

新增「戰場目標」，依真正的兵營、木作營、軍隊數量與敵方可見主城更新。建造會選現有工匠並進入正常預覽；集結引導到合法生產建築，偵察使用公共地圖可走格，攻城只鎖定當前可見敵方主城。七種兵種有簡短用途說明，沒有贈送資源或把霧外敵情當目標。

選單建築 atlas 改為專用 100,140 bytes 縮圖；戰場三張 WebP 圖集共少 923,467 bytes。逐像素核對 alpha 與所有非透明 RGB 都相同，完全透明像素的 RGB 有重設，沒有稱整份 RGBA byte-identical。PNG 原檔保留。[編碼量測](evidence/r26/runtime-art-report.json)

首批下載依玩家初始視野與己方單位決定；未出現的兵種與外怪延後下載。後續下載有可見狀態提示，單人權威模擬等候素材，既有呈現走完剩餘位移；線上模擬不因本機下載暫停。續玩來源保留到同步啟動成功，失敗重試仍帶回同份存檔。

同機空快取、400 KiB/s／60ms 人造網路的前期單次比較，開始至可操作 13.095→7.656 秒，該階段內容 5,116,441→2,880,885 bytes。選單可操作時間 5.570→5.643 秒，沒有改善。這份樣本在最後鎖定 build 前測量，與正式包覆測分開記錄；不代表所有真實網路，也不是三跑中位。[完整載入稽核](LOAD_AUDIT_R26.md)

## 正式包覆測

鎖定 `index-BH8sAHob.js` 與 `/village-siege/` base 後，其他體驗及測試停止，再以相同人造網路量測單次冷載：開始至可操作 7.615 秒，比基準少 41.9%；首次下載請求 19→10、內容少 43.7%。選單可操作為 5.649 秒，仍沒有改善。

桌機 1280×720 與 Chromium 觸控模擬 844×390，各自單一 context、暖機後三跑五秒，活動戰場的 rAF p95 中位皆為 16.8ms。這是 Windows 上的新局場景，不是所有實機或大規模戰場保證。正常 PWA 下載完成後，真離線重載與開始戰役通過，該次戰場可操作 651ms。下載完成後的報告運算曾有測試工具 ReferenceError，保留於摘要，沒有當成遊戲錯誤或隱藏。[正式包玩家驗收](evidence/r26/final-player-qa-summary.json)
