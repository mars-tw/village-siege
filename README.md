# Village Siege／村莊攻防

Village Siege 是 MIT 授權的開源瀏覽器即時戰略遊戲。它採用原創的中世紀等角視角點陣美術與自有介面；節奏參考經典 RTS，不包含《世紀帝國 II》的名稱、素材、音效或介面複製品。

## 1.2：移動、進場與出征指引（2026-10-02）

修正工匠與軍隊走路時被位置更新打斷的跳動，停下前會走完最後一段；單向圖集依左右轉向，六方向圖集保留各自原圖。新增「戰場目標」，串接生產、集結、偵察與攻城，操作使用正常資源與指令。

選單改用專用縮圖，戰場保留相同可見像素的 WebP 地景；未出現的兵種與怪物延後下載。相同 400 KiB/s、60ms 模擬網路的單次前後量測，開始至可操作由 13.1 秒降為 7.6 秒；這是受控測量，實際公網速度依網路而異。

## 1.0 正式公開版（2026-10-01）

1.0.0 是 Village Siege 第一個正式公開的單機 Web／離線 PWA 版本，規則版本為 `village-siege/0.20.0`。三張村莊地圖、三種難度、五種 AI 性格、三階段聚落、七項科技、七種兵種、三種野外怪物與四條勝利路線都已接上同一套決定論規則。

**[立即遊玩最新版本](https://mars-tw.github.io/village-siege/play.html?v=1.2.0)**

這次把完整發展流程需要的地圖有限資源補足：每方家園木材總量由 1,000 提高到 6,000，石材由 700 提高到 4,000，採集速度、資源耗盡與糧田復育規則不變。也修正友軍占住捷徑時的繞行、非城門最後目擊帶入 `undefined` 造成存檔／重播 hash 不一致，以及 AI 未接手已付款工地的問題。

舊 `village-siege/0.19.0` 存檔與重播會先完整驗證，再明確升級到 `0.20.0`；已付建造與生產成本、已採集數量都會保留。驗證失敗時不會取代目前戰局或改動原檔。

戰場新增常駐科技與時代面板，原生對話框會列出建築、成本、聚落階段、前置科技、研究中與已完成狀態，並直接引導玩家選取正確建築操作。單機戰役每 30 秒及離開戰場時自動儲存到 IndexedDB，保留 `latest` 與 `previous` 兩個檢查點；主選單的「繼續戰役」可還原進度，最新檔損壞時會改讀上一個有效檢查點。

操作同步整理：`Esc` 開啟系統選單，按住 `Shift` 拖曳可框選多個單位，直接點可見的中立野怪即可攻擊；角色動畫依 `requestAnimationFrame` 逐影格更新。

本次交付範圍不含 Android／iOS 簽署原生 App、長期公開 WSS 多人服務與劇情戰役。多人伺服器與部署範本仍保留給本機開發、自架和後續公開驗收。


## 施工接續修正（0.22.1，2026-10-01）

施工途中可轉去其他工地，再選工匠點原工地繼續施工；選取工地也有「繼續施工」按鈕。接續保留進度與已付材料，不重扣建造費。0.22.0存檔與重播保持相容。

## 人物與地圖重製（0.22.0，2026-10-01）

實際戰場換成統一的半寫實中世紀畫風：專屬工匠、七兵種、三外怪、原創樹林、石礦、田地與地表，全程使用點陣圖，不使用SVG。工匠、戰士、槍盾兵和弓箭手各有六個獨立朝向，其他四兵種與三外怪各有24格單一朝向動畫。

三張地圖擴大為32×24。每方從主城與三名工匠開始，家園開放建造、採集與集結；寬通道連接河流渡口或山地隘口，外怪營地移到側翼。選取才顯示人物名稱與攜帶數，桌機資源、目標與提示分區顯示。

正常標準AI實測完成採集、施工、訓練12名軍人、探索、交戰與合法中域勝利。規則版本更新為0.19.0，舊版存檔與重播會依版本檢查拒絕匯入，原檔保留。詳見[角色、地圖與玩法設計](docs/FRONTIER_GAME_DESIGN_0.22.zh-TW.md)及[真實對局證據](docs/evidence/r22/open-village-playthrough.json)。

## 開啟遊戲

- 角色動作表採戰役場景 lazy-loading：主選單不先下載整套戰鬥素材，進入單人戰役時才載入必要圖集並顯示載入狀態。
- 摧毀敵方議事核心會啟動 60 秒重建寬限；也可藉由殲滅全部有效戰力、持有一座拓界銅標 90 秒，或在開局 60 秒後累積控制中域 120 秒獲勝。
- Colyseus 將 2～5 人六碼房大廳與私有戰局拆開；伺服器以不同的 32-byte 內部能力替每位玩家預約席位並鎖滿戰局，瀏覽器只消費自己的 Colyseus reservation。戰局以固定 10 Hz 執行同一份 shared 模擬，只接受不含身分權限的指令 intent。
- 每位連線只收到自己的迷霧過濾 Snapshot／事件；相同序號不會跨玩家混回執，偽造控制與額外身分欄位會被拒。TASK-020 已完成 120 秒恢復租約、checkpoint＋批次 journal、指令結果 ledger、Redis/PostgreSQL fencing 與真實 socket 重連測試。

## 本機啟動

先在專案根目錄安裝鎖定版本：

```powershell
npm ci
```

開啟第一個終端機啟動多人伺服器：

```powershell
npm run dev:server
```

伺服器預設監聽 `http://localhost:2567`。再於第二個終端機啟動遊戲：

```powershell
npm run dev:client
```

開啟 Vite 顯示的網址即可選擇單人模式，或在多人模式建立房間。第二個瀏覽器／無痕視窗可輸入同一個六碼房號加入。

單機戰役操作：

- 點我方工匠或建築選取；`Shift` 可加選。點空地讓已選單位移動，點敵人進攻。
- 選取工匠後可直接按「採糧／伐木／採石」，或點木材、糧食、石礦持續採集；滿載後會自動送回合法卸貨點，也可按「卸糧／卸木／卸石」（混合載貨時為「卸全部」）或直接點主城、木作營、糧秣所手動送貨。按 `B` 或底部「建造」，選建築後再點有效空地放置。
- 測界雙葉門放置時可用固定指揮塢切換北東／南東軸；完工後點選城門即可開啟或關閉。城門格內有單位時，關門命令會被權威規則拒絕，避免把部隊夾在門內。
- 選取議事堂可訓練工匠；選取已完成的對應軍事建築，才可把該建築負責的兵種加入訓練佇列。建築底部第五格開啟佇列，第六格進入集結選點；取消工作必須再按一次確認。
- 純軍隊選取時，固定七格依序提供攻擊移動、雙點巡邏、編隊、姿態、兵種技能、停止與系統。攻擊移動會沿途尋敵並在交戰後續行；編隊提供橫列、楔形、方陣，姿態提供主動、守備、堅守。選取工匠則可點「修復」後指定受損友方建築。
- 拖曳空地平移鏡頭；`WASD` 平移、滾輪縮放、`P` 暫停、`R` 重開。`Esc` 會依序取消戰術選點、從取消確認返回佇列、從佇列／集結選點返回建築主指令、取消建造，最後才返回戰前會議。
- 主城、人口、成本、採集、施工、訓練、傷害與勝負皆由同一份共享狀態決定，畫面不會自行增加假資源。

手機與觸控裝置操作（568×320、667×375、844×390、390×844 與 1366×1024 已驗證）：

- 點我軍選取、點地移動、點資源採集、點敵軍攻擊，拖曳空地可平移鏡頭；工匠列另有「採糧／伐木／採石」直接鍵，解決小螢幕上資源與建築命中區相鄰的問題。工匠滿載會自動卸貨，指令列也提供手動卸貨。
- 底部是依目前選取物切換的單列 Canvas 指揮塢；十三種可建建築分成四頁，以「下一頁／回首頁」循環切換。建築旋轉、城門開關、軍隊的攻擊移動、巡邏、編隊、姿態、技能、停止、系統，以及生產佇列、取消確認、集結與修復選點，都在同一排七格內完成，不會疊出第二層視窗。
- 遊戲會偵測觸控裝置、可視瀏覽器高度與橫直方向，以 `EXPAND` 模式填滿可用畫面；直向時會提示將手機橫放。
- 手機點「互動教學」或「開始單機戰役」時會在該次使用者操作中要求全螢幕；戰場內可由 **系統** 切換全螢幕。若瀏覽器不支援 Fullscreen API，則改用最大可視滿版並顯示提示。
- 568×320 的主命令觸控區實測至少約 52×52 CSS px；上下資訊列與指揮塢均留在遊戲畫布內且不重疊。
- Canvas 內提供拉近、拉遠、暫停、選取工匠／軍隊與全螢幕；每個可見 Canvas 指令都有鍵盤／螢幕閱讀器代理。

若伺服器不在預設位置，啟動或建置客戶端前設定：

```powershell
$env:VITE_COLYSEUS_URL = "http://127.0.0.1:2567"
npm run dev:client
```

## 驗證與多人 smoke test

完整型別檢查、共享模擬測試與正式建置：

```powershell
npm run verify
```

可重跑的本機多人測試會自行建置、啟動獨立伺服器、建立兩個客戶端，最後關閉連線與伺服器：

```powershell
npm run smoke:multiplayer:local
```

真實關閉 WebSocket、恢復 Snapshot 並驗證 pending 指令 exactly-once 重播：

```powershell
npm run smoke:multiplayer:recovery:local
```

它驗證以下行為：

- 房主建房、第二位玩家依房號加入同一大廳。
- 非房主無法開始；玩家未全數準備時房主也無法開始。
- 非法 ready payload 遭拒。
- 大廳為兩位玩家分配同一個獨立私有戰局，但給予不同的穩定玩家 ID 與已預約席位；外部客戶端不能直接建立或搶佔權威戰局。
- 雙方在相同 sequence 下只收到自己的回執；身分欄位注入與控制對方單位都遭拒。
- 雙方收到各自迷霧過濾的權威 frame，完整 canonical state 不進 room schema；合法產兵會由伺服器實際扣除資源。

若已另行啟動伺服器，可改用：

```powershell
npm run smoke:multiplayer
```

以 `COLYSEUS_URL` 指定非預設測試端點；自啟測試則可用 `SMOKE_PORT` 改變預設的 `26567` 連接埠。

## 建置與發布

正式容器部署優先使用 GHCR 的 `village-siege-client`／`village-siege-server` release 映像。前端映像不寫死網域，啟動時由 `PUBLIC_CONNECT_ORIGIN` 提供不可快取的 `/runtime-config.js`；拉取與 TLS/WSS 設定見 [production 操作指南](docs/PRODUCTION_OPERATIONS.zh-TW.md)。

只有發布到無法提供 runtime config 的純靜態網站／CDN 時，才把公開的 Colyseus HTTPS 端點寫入自建 bundle：

```powershell
$env:VITE_COLYSEUS_URL = "https://game.example.com"
$env:VITE_MULTIPLAYER_ENABLED = "true"
npm run build
```

- 將這條替代路徑產生的 `apps/client/dist/` 發布至靜態網站或 CDN；不要把它誤當成可跨網域重用的 GHCR 映像。
- 以 `PORT` 指定伺服器連接埠；自有網域部署須先把客戶端來源（只填 origin，不含路徑）加入逗號分隔的 `ALLOWED_ORIGINS`，再執行 `npm run start:server`。官方 GitHub Pages origin 已內建；非 production 模式另允許 loopback HTTP 方便本機開發。
- HTTP 配對與 WebSocket 握手共用 exact-origin 白名單，瀏覽器端另有 CSP；production 拒絕所有明文瀏覽器 Origin，公開部署仍須在反向代理終止 TLS、使用 `wss`，並通過邊緣速率限制、監控與健康檢查。
- TASK-023 已加入前端／伺服器 Dockerfile、單 replica Compose、Redis/PostgreSQL 持久卷、健康／版本端點、SBOM 與 CI；操作方式與限制見 [自架指南](docs/SELF_HOSTING.zh-TW.md)。
- TASK-024 已加入獨立 production Compose、Caddy 自動 TLS/WSS、Docker secrets、internal-only metrics、Prometheus/Grafana、age 加密備份與雙確認還原範本；見 [production 操作指南](docs/PRODUCTION_OPERATIONS.zh-TW.md)。範本已完成不等於官方公開主機已部署。

### 自有設計與完整開源

本專案的「私有化」指 **改造成 Village Siege 自己的品牌、玩法、美術與世界觀**，不是把程式碼鎖進私有倉庫。客戶端、伺服器、共享規則、美術來源與無秘密的 TLS/WSS、備份、監控範本都以 MIT 完整開放；只有密碼、Token、私鑰等實際憑證不得提交。完整架構見 [v3 authoritative RTS architecture](docs/architecture/authoritative-rts-v3.md)。

- v3 開發分支已加入三階段聚落、七項科技、資源搬運、戰爭迷霧、築城與破口、三張強化村莊地形、工作平民、權威野外怪物、策略 AI、四條決定論勝途、v0.13 存檔／重播、七段互動教學、伺服器權威戰場、120 秒耐久斷線恢復，以及 v0.17／v0.18 的線上插值與逆境多人 E2E。TLS/WSS、監控與加密備份範本已完成；尚未完成的是把它們部署到真實公開主機並通過 live gate。
- 建築占地、靜態阻擋繞路、同隊單位逐 tick 格位預約與有界局部避讓已由共享規則處理，也已加入橫列、楔形與方陣的穩定格位編隊；尚未加入長距離路徑快取，大量單位擠進單格入口時仍會依固定順序排隊。
- 松林堡、河谷鎮與高地寨已有三張獨立地形、築城拓撲與進攻路線；松林堡有 3% 採集加成、河谷鎮有 3% 移速加成、高地寨有 4% 守望塔護甲，且都由共享模擬計算。目前三村仍共用同一套七項科技樹，尚未拆成各村專屬研究分支。
- 工匠暫時共用戰士動作表並加上工具標記；七種軍事單位皆有正式動作表，但工匠專屬採集／施工影格仍待製作。
- 多人伺服器已完成大廳／戰局分房、私有席位、固定 10 Hz shared 模擬、玩家專屬 Snapshot／事件、真實指令驗證與 `VillageAssaultScene` 純網路 Snapshot 渲染；目前限制是公開 Pages 尚未連上長期運作的 WSS 服務。
- 現有角色動作表完成六動作、每動作四個獨立影格；戰士與弓箭手已改用六方向各自獨立繪製的動作表，切換方向時不再鏡像。其餘五種軍事單位與三種野怪仍使用單一母版，會依路線逐一通過同一套 144 格靜態與瀏覽器門檻後再升級。
- 本機預設仍是單一 Node.js 程序；設定 Redis 與 PostgreSQL 後可使用 120 秒耐久恢復、checkpoint／journal 與 fenced lease。程序內重連可恢復，但啟動後自動掃描並重建所有舊房間、跨程序 presence、自動水平遷移與跨區災難復原尚未完成。
- 房號由客戶端提出，伺服器會正規化與篩選，但尚未提供全域唯一性保證或邀請權限。
- 目前已有伺服器權威驗證、每玩家訊息速率限制、私人席位 token、exact-origin 與霧區資料邊界；仍沒有帳號系統、管理員工具、觀戰隱私控制與邊緣 DDoS 防護，因此不可只啟動 Node 程序就視為網際網路公開服務的安全完成品。
- 戰役素材已延後到進入場景時載入；JavaScript 場景程式與多人功能仍可在後續版本繼續拆分 chunk，以降低首次開啟的傳輸量。
- 2026-07-21 執行 `npm audit --omit=dev` 為 0 vulnerabilities。伺服器直接使用 `@colyseus/core`、schema、WebSocket transport 與 Express 相依鏈，沒有引入未使用的 Colyseus auth/playground meta-package；公開發布前仍應在 CI 持續執行 audit 與版本審查。
